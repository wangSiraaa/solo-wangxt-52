# 离线农资促销配单工具（虚构演示）

纯前端离线工具：店员按农户的作物、区域与需求数量整理采购清单，自动执行**虚构**销售规则
（适用作物、禁售区域、互斥组、每农户限购、阶梯价、促销库存）并打印配单。

- React 18 + TypeScript + Vite
- **decimal.js**：阶梯价/促销价/满减全部用 Decimal 计算，两位小数四舍五入
- **Dexie + IndexedDB**：本地库存、草稿、跨标签页预占记录，全部在本机；无后端、无网络请求
- 货架与清单联动：加入即预占促销库存，移除/失效即释放
- **不输出任何农药使用、剂量或混配建议**；农药条目只承载销售规则，商品全部为虚构

## 运行

```bash
npm install
npm run dev       # 本地开发
npm test          # 31 个单元测试（vitest + fake-indexeddb）
npm run build     # 类型检查 + 生产构建
```

## 领域规则落点

| 需求 | 实现 |
| --- | --- |
| 适用作物 / 禁售区域 / 互斥组 / 限购 | `src/data/catalog.ts`（虚构商品）、`src/lib/eligibility.ts` |
| 跨包装规格（袋/中包/箱）按 factor 换算基础单位 | `PackSpec.factor`，所有规则按基础单位汇总 |
| 阶梯优惠 decimal.js 计价 | `src/lib/pricing.ts` `lineCost` |
| 两个优惠不能叠加，解释采用哪种方案 | `priceDraft` 比较方案 A（单品阶梯+促销价）与方案 B（原价+满减），取应付低者，`explanation` 写明双方金额；打印在「金额来源」 |
| 加入预占、移除释放 | `src/lib/reservations.ts` 事务化 `syncReservations`，失效行不预占 |
| 拆行绕不过限购 | 同一 SKU **跨整单全部行、跨包装** 汇总后判定，超限时所有同 SKU 行标 `LIMIT_EXCEEDED` |
| 筛选变化不清空草稿 | 分类/关键字筛选是 `Shelf` 组件本地 state；区域/作物切换只重算资格，行全部保留（失效行红底标注原因） |
| 导入重复编号展示冲突而非覆盖 | `src/lib/importDraft.ts`：与草稿重复、文件内重复分别提示，默认跳过，可手动「仍加入为新行」，旧行永不被改 |
| 多标签页争用 | 预占按会话（标签页）隔离，2 秒轮询 + Dexie live query 刷新；崩溃标签页靠 15 秒心跳过期兜底释放 |
| 打印区分有效/待确认/失效 + 金额来源 | `src/components/PrintBill.tsx`，三段分区 + 逐行金额来源 + 方案对比，调用浏览器打印（可另存 PDF） |

行状态：
- **有效（绿）**：全部规则通过，可成交
- **待确认（黄）**：作物不匹配，或促销库存被其他标签页占用导致部分数量按阶梯价；行保留、库存仍预占，需店员线下核实
- **失效（红）**：区域禁售、停用、未知编号、包装失效、互斥冲突、物理库存不足、超限购；不计价、不预占

## 要求的验证案例

### 案例 1：跨包装规格 + 拆行绕限购

1. 作物选「玉米」，加入 P004（限购 40 袋）：选「中包（5 袋）」数量 3，再以「袋」加 25 → 共 40，全部有效，金额按总量所在阶梯档。
2. 再加 1 袋（41 > 40）→ **三行同时变红**，原因均为「超过每位农户限购量；已按同一编号跨整单汇总，拆行不能绕过」。
3. 切换某行包装从「中包」为「袋」时基础单位即时重算，旧预占键（含 lineId/sku）随同步释放、按新值重占（测试见 `limits.test.ts`）。

### 案例 2：区域切换使部分商品失效

清单中同时放 P001（西部禁售）、F001（全国通用）、S001（北方禁售），作物选「水稻」：

- 北方平原：S001 失效（红），P001/F001 有效；
- 切到西部高原：P001 失效、S001 转有效，F001 始终有效。
- **行不会被删除**；切回原区域即恢复，预占随状态同步释放/重占（`eligibility.test.ts` 中「区域切换」用例）。

### 案例 3：多标签页争用促销库存

1. 在两个浏览器标签页打开本工具（各为独立会话）。
2. A 标签页给 F001 加 50 袋（促销库存 80）；B 标签页加入 40 袋。
3. B 的行变**待确认**：促销只剩 30 件（行内显示「含促销价 ×30」），原因「促销库存被其他标签页预占，部分数量将按阶梯价」；顶栏显示在线标签页数。
4. A 移除该行（或切到别的草稿）→ 约 2 秒内 B 恢复 40 件促销价、状态转有效。
5. 直接强杀 A 标签页：15 秒心跳过期后其预占被兜底释放（`reservations.test.ts` 自动化覆盖加入/释放/争用/崩溃回收）。

### 打印检查

清单含三类行时点「打印 / 导出清单」：
- 一、有效项；二、待确认项（黄字声明须核实）；三、失效项（不计价不销售）；
- 第四节「金额来源与优惠方案」逐行注明多少件按促销价（预占）、多少件按哪一阶梯档，并说明 A/B 两方案为何取其一；
- 页脚声明：虚构商品、不提供农药使用/混配建议、促销库存为本地预占。

### 导入冲突

「导入清单」粘贴：

```json
{"lines":[{"sku":"F001","packId":"bag","packs":10},{"sku":"F001","packId":"box","packs":1},{"sku":"X9","packId":"bag","packs":2}]}
```

草稿已有 F001 时：第一行红标「草稿中已存在同一商品编号（默认跳过，不覆盖）」并回显现有行包装/数量；第二行黄标「文件内重复」默认跳过；X9 黄标「本地货架无此编号」，可加入但加入后即为失效行。确认后仅所选行追加，现有行数量不变。

## 代码结构

```
src/
  data/catalog.ts        虚构商品与规则（区域/作物/互斥/限购/阶梯/促销库存/满减档）
  lib/money.ts           Decimal 封装
  lib/pricing.ts         阶梯价、促销价、A/B 互斥方案选择与解释
  lib/eligibility.ts     有效/待确认/失效判定、限购汇总、促销库存跨行分配
  lib/reservations.ts    预占事务、跨会话争用、心跳过期回收
  lib/importDraft.ts     JSON/CSV 解析、重复编号冲突报告
  lib/bill.ts            打印账单模型（分组 + 金额来源）
  db.ts                  Dexie 表结构与虚构库存播种
  components/            Shelf / CartList / PricingSummary / ImportModal / PrintBill
  test/                  31 个测试
```
